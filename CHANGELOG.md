## [Unreleased]

### Added
- A corpus test on real themes: the 20 most downloaded extensions of the Themes category of Open VSX on 20 November 2026, 178 theme files, at fixed versions with the SHA-256 of each `.vsix` (`test/corpus/extensions.json`). `npm run corpus` downloads them into a cache that is not committed; `npm run test:corpus` extracts them as VS Code installs them, with yauzl, audits them in both modes, and checks their themes and warnings against `test/corpus/expected.json`. The CI runs it with a cache. `node scripts/corpus.ts --update <id>@<version>` moves an extension to another version ([#10](https://github.com/mickaellherminez/vscode-theme-audit/issues/10)).
- The command audits theme files and extension folders: `vscode-theme-audit <theme file or extension folder>...`. A text report gives each failed check with its colors, the value measured and the minimum, the pairs of colors that a vision confuses, and a summary. `--json` prints the report as JSON for CI, in format 1, described by `schema/report-v1.schema.json`, published with the package. `--strict` applies the rules of 365 Day & Night. Exit codes: `0` when every check passes, `1` when a check fails, `2` when a theme cannot be read or the command is misused. A theme file takes its type and name from the extension that declares it, or from its `type` field ([#9](https://github.com/mickaellherminez/vscode-theme-audit/issues/9)).
- The checks of the audit, ported from `audit.py` and `variety.py` of 365 Day & Night: WCAG 2.2 contrast of the text and of each syntax and semantic color on its backgrounds (7:1 in high contrast themes), the styles of WCAG 1.4.1, the colors that must stay distinct with color blindness (CIEDE2000 of at least 7 with every model), and achromatopsia for information. By default they read the colors that VS Code shows, defaults included: a missing color is information, the text of the terminal is measured after the minimum contrast of VS Code (computed as xterm.js does), the main text needs 4.5:1 (7:1 in high contrast), and the styles are information. The strict mode applies the rules of 365 Day & Night: colors set by the theme only, 7:1 for the main text, the styles required, the terminal measured with the colors of the theme, required keys and semantic rules, the status bar button, and the variety between the themes of one type. In strict mode, the 48 themes of 365 Day & Night give the same results as `audit.py` and `variety.py`: 13,212 checks, 7,104 pairs and the variety of 4 variants, to 0.01 ([#8](https://github.com/mickaellherminez/vscode-theme-audit/issues/8)).
- The workbench colors of a theme as VS Code shows them, with the defaults of VS Code for the keys the theme leaves out, for the four theme types, and where each color comes from: the theme, a default of VS Code, or derived from other keys, which are listed. The 1,007 defaults of VS Code 1.147.0 are extracted from its sources by `scripts/vscode-colors.ts`, with the colors of its built-in Git extension; the transforms of VS Code (transparent, opacity, darken, lighten, opaque, mix, one of, less prominent, if defined then else) and its `Color` are ported with their tests. The colors that an extension contributes (`contributes.colors`) are read too. A missing key is information; a strict mode makes it a failure, as in the audit of 365 Day & Night. Checked against VS Code itself with `scripts/vscode-oracle.ts`: 0 difference on 226,726 colors of 226 themes with VS Code 1.146.0, and a sample of 251 keys of four test themes in the tests ([#7](https://github.com/mickaellherminez/vscode-theme-audit/issues/7)).
- The style of a semantic token, as VS Code shows it when a theme sets `semanticHighlighting`: the rules of `semanticTokenColors` (type, modifiers and language, the best score winning for each property), then the TextMate scopes that VS Code probes for each token type, including those of its built-in JavaScript and TypeScript extensions. Ported from VS Code with its tests. Loading a theme now warns about semantic colors that VS Code cannot read, and refuses a theme that VS Code refuses ([#6](https://github.com/mickaellherminez/vscode-theme-audit/issues/6)).
- The style of a token from its scopes, as VS Code shows it with TextMate grammars: the matching of vscode-textmate (scope prefixes, comma-separated selectors, parent scopes and `>`, the most specific rule wins), ported with its tests, and the rules that VS Code gives it (the editor colors as defaults, colors written in full, log colors). Checked against vscode-textmate itself, on random themes in the tests and on 11,036 styles of the 178 themes of the corpus, with no difference.
- Reading a color theme the way VS Code does: JSON with comments and trailing commas, `include`, `"default"` to remove an included color, the old `settings` format, `semanticTokenColors`, and the themes of an extension folder with their `uiTheme` and translated labels. Warnings for what VS Code accepts but probably was not meant, such as a color it shows in red. TextMate theme files (`.tmTheme`) are not supported yet.
- The measuring tools, ported from `colorlib.py` of 365 Day & Night with the same results: WCAG 2 contrast, alpha compositing, CIELAB, CIE76 and CIEDE2000, and the color blindness simulations of Machado et al. 2009, Brettel et al. 1997 and Viénot et al. 1999, with the models kept for each deficiency. Tested against published data (Sharma et al. 2005, Machado et al. 2009), DaltonLens, and the results of `colorlib.py`.
- The package and its command, with `--help` and `--version`. TypeScript run directly by Node.js 22.18 or later, ESLint, tests with the test runner of Node.js, CI on Node.js 22 and 24, and CodeQL ([365-daynight-vscode-theme-ext#100](https://github.com/mickaellherminez/365-daynight-vscode-theme-ext/issues/100)).
